# Noisy Room Skill Tests

This directory contains the pytest-driven harness for testing the live `noisy:tmd` skill through Codex, deterministic shape, marketplace, and discovery coverage for `noisy:local-skill`, and discovery coverage for `noisy:watch-task`.

## Run

```sh
uv run pytest
```

The default pytest suite invokes real `codex` commands for discovery and behavior. It is intentionally an end-to-end harness, not a contract-only unit test suite.

Run by speed group:

```sh
uv run pytest tests/fast
uv run pytest tests/cli_smoke
uv run pytest tests/live_codex
```

Each test case lives in its own file, so a single scenario can run directly:

```sh
uv run pytest tests/fast/test_taskmd_shape.py
```

## Shape

- `tests/fast/` contains file-only and generated-workspace checks with no external CLI calls.
- `tests/cli_smoke/` contains CLI discovery smoke tests without model calls.
- `tests/live_codex/` contains model-backed Codex behavior tests.
- `tests/scenario_data.py` contains shared scenario markdown fixtures.
- `tests/harness.py` creates minimal fake workspaces, wires the Codex `noisy:tmd`, `noisy:local-skill`, and `noisy:watch-task` skills as symlinks to the live skills, runs Codex CLI scenarios, and validates outputs.
- `tests/schemas/verifier-result.schema.json` defines the structured result returned by the Codex semantic verifier.
- `/tmp/noisy-room-tests/` is generated by default.

Each behavior scenario uses a minimal workspace. It does not create `.git`, `README.md`, or `AGENTS.md` unless a future scenario needs them.

## Generated Runs

Run directories are created under:

```text
/tmp/noisy-room-tests/<scenario>-<id>/
```

Set `NOISY_TEST_RUNS_DIR` to use another generated-run root.

Successful runs are deleted by default. Failed runs are preserved with the fake workspace and command artifacts so failures can be inspected.

Set this to keep successful runs too:

```sh
NOISY_KEEP_TEST_ENVS=1 uv run pytest
```

## Current Coverage

- Discovery smoke test: verifies Codex sees `noisy:tmd`, `noisy:local-skill`, and `noisy:watch-task` through fake workspace symlinks. This does not launch a watcher or exercise desktop chat messaging.
- Marketplace shape test: verifies the repo marketplace exposes the `noisy` plugin from `./plugins/noisy` with the required installation policy.
- Local-skill shape test: verifies bundled default-source bootstrap, the no-argument full install/uninstall form, scriptless per-skill operations, install-scope-aware registries, Preview/Apply scope binding, project-owned provenance, and recoverable mutations.
- Taskmd shape test: verifies active Roadmap items use Roadmap IDs (`R<DOCKEY>-<NNN>` for new items, legacy `R###` accepted) plus required `created_at`, `deps`, `parallels`, `Rationale`, and `Task` fields.
- New task doc scenario: invokes `$noisy:tmd -n` with `source.md`, validates the required markdown contract, then asks a Codex verifier for a structured semantic pass/fail result.
- Codex Continue execution-wave scenario: invokes `$noisy:tmd -c` through Codex CLI `--json` on a task doc with two compatible parallel Roadmap items, checks both task work and the task doc Worklog, and verifies Worklog records the actual execution mode without requiring streamed subagent events.

The Codex Continue scenario proves a compatible execution wave through observable task work plus Worklog state, without requiring first-class subagent stream events. The New scenario validates the generated task doc with the same deterministic checks and then reuses the Codex semantic verifier.
