# Noisy Room Skill Tests

This directory contains the pytest-driven harness for testing the live `noisy:taskmd` skill through Codex and Gemini CLI wiring.

## Run

```sh
uv run pytest
```

The default pytest suite invokes real `codex` commands for Codex behavior and real `gemini` commands for non-model Gemini discovery. It is intentionally an end-to-end harness, not a contract-only unit test suite.

## Shape

- `tests/test_taskmd_skill.py` contains the first scenarios.
- `tests/harness.py` creates minimal fake workspaces, wires `.codex/skills/noisy:taskmd` and `.gemini/skills/taskmd` as symlinks to the live skill, runs CLIs, and validates outputs.
- `tests/schemas/verifier-result.schema.json` defines the structured result returned by the Codex semantic verifier.
- `/tmp/noisy-room-tests/` is generated by default.

Each behavior scenario uses a minimal workspace. It does not create `.git`, `README.md`, or `AGENTS.md` unless a future scenario needs them.

## Generated Runs

Run directories are created under:

```text
/tmp/noisy-room-tests/<scenario>-<id>/
```

Set `NOISY_TEST_RUNS_DIR` to use another generated-run root.

Successful runs are deleted by default. Failed runs are preserved with the fake workspace and command artifacts so failures can be inspected.

Set this to keep successful runs too:

```sh
NOISY_KEEP_TEST_ENVS=1 uv run pytest
```

## Current Coverage

- Discovery smoke test: verifies Codex sees `noisy:taskmd` through the fake workspace symlink.
- Gemini wiring test: verifies the fake workspace sees `taskmd` as the Agent Skill and `/noisy:taskmd` as the custom command wrapper.
- Gemini discovery smoke test: verifies `gemini skills list --all` sees `taskmd` without making a model call.
- New task doc scenario: invokes `$noisy:taskmd --new` with `source.md`, validates the required markdown contract, then asks a Codex verifier for a structured semantic pass/fail result.

## Optional Gemini Behavior

Set this to run the live Gemini model scenario:

```sh
NOISY_RUN_GEMINI_E2E=1 uv run pytest
```

That scenario invokes `/noisy:taskmd --new` through Gemini CLI, validates the generated task doc with the same deterministic checks, and then reuses the Codex semantic verifier.
