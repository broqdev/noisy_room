# Noisy Room Skill Tests

This directory contains the pytest-driven harness for testing the live `noisy:taskmd` skill through Codex and Gemini CLI wiring.

## Run

```sh
uv run pytest
```

The default pytest suite invokes real `codex` commands for Codex behavior and real `gemini` commands for non-model Gemini discovery. It is intentionally an end-to-end harness, not a contract-only unit test suite.

Run by speed group:

```sh
uv run pytest tests/fast
uv run pytest tests/cli_smoke
uv run pytest tests/live_codex
NOISY_RUN_TASKMD_RT_E2E=1 uv run pytest tests/live_roundtable
NOISY_RUN_GEMINI_E2E=1 uv run pytest tests/live_gemini
```

Each test case lives in its own file, so a single scenario can run directly:

```sh
uv run pytest tests/fast/test_taskmd_rt_shape.py
```

## Shape

- `tests/fast/` contains file-only and generated-workspace checks with no external CLI calls.
- `tests/cli_smoke/` contains CLI discovery smoke tests without model calls.
- `tests/live_codex/` contains model-backed Codex behavior tests.
- `tests/live_roundtable/` contains opt-in taskmd-rt E2E tests that call both Codex and Gemini.
- `tests/live_gemini/` contains opt-in model-backed Gemini behavior tests.
- `tests/scenario_data.py` contains shared scenario markdown fixtures.
- `tests/harness.py` creates minimal fake workspaces, wires `.codex/skills/noisy:taskmd` and `.gemini/skills/taskmd` as symlinks to the live skill, runs CLIs, and validates outputs.
- `tests/schemas/verifier-result.schema.json` defines the structured result returned by the Codex semantic verifier.
- `/tmp/noisy-room-tests/` is generated by default.

Each behavior scenario uses a minimal workspace. It does not create `.git`, `README.md`, or `AGENTS.md` unless a future scenario needs them.

## Generated Runs

Run directories are created under:

```text
/tmp/noisy-room-tests/<scenario>-<id>/
```

Set `NOISY_TEST_RUNS_DIR` to use another generated-run root.

Successful runs are deleted by default. Failed runs are preserved with the fake workspace and command artifacts so failures can be inspected.

Set this to keep successful runs too:

```sh
NOISY_KEEP_TEST_ENVS=1 uv run pytest
```

## Current Coverage

- Discovery smoke test: verifies Codex sees `noisy:taskmd` through the fake workspace symlink.
- Roundtable discovery smoke test: verifies Codex sees `noisy:taskmd-rt` through the fake workspace symlink.
- Roundtable shape test: verifies `noisy:taskmd-rt` uses direct skill logic instead of a helper script.
- Roundtable fake-delegate test: invokes `noisy:taskmd-rt` through Codex and uses deterministic fake delegated CLIs to verify one round produces Gemini then Codex Worklog entries, even when Gemini prints a recovered edit-tool error before succeeding.
- Roundtable real E2E test: opt-in scenario that invokes `noisy:taskmd-rt`, wraps the real `codex` and `gemini` binaries with logging shims, and asserts the delegated call log starts with real Gemini then real Codex.
- Gemini wiring test: verifies the fake workspace sees `taskmd` as the Agent Skill and `/noisy:taskmd` as the custom command wrapper.
- Gemini discovery smoke test: verifies `gemini skills list --all` sees `taskmd` without making a model call.
- New task doc scenario: invokes `$noisy:taskmd --new` with `source.md`, validates the required markdown contract, then asks a Codex verifier for a structured semantic pass/fail result.

## Optional Gemini Behavior

Set these to run optional live model scenarios:

```sh
NOISY_RUN_TASKMD_RT_E2E=1 uv run pytest tests/live_roundtable
NOISY_RUN_GEMINI_E2E=1 uv run pytest tests/live_gemini
```

The roundtable scenario invokes `$noisy:taskmd-rt -r 1` through Codex and proves the delegated `gemini` and `codex` commands ran before validating the task doc. The Gemini scenario invokes `/noisy:taskmd --new` through Gemini CLI, validates the generated task doc with the same deterministic checks, and then reuses the Codex semantic verifier.
